# SYMBIOS hands-free, context, wake, and display review

Status: staged source changes only. No gateway deployment, firmware build
approval, device connection, or flash is authorized by this document.

## Outcome staged in source

- The device identity is **SYMBIOS** and the intended spoken phrase is
  **“Hi Symbios.”** The current installed WakeNet asset remains **“Hi ESP”**
  until a genuinely trained English WakeNet model is obtained and reviewed.
- The Symbios LAFVIN build uses its existing AFE VAD result to submit an
  automatic turn after at least 300 ms of speech followed by 1,200 ms of
  silence. Short wake-acknowledgement/noise bursts do not arm the timer. DOWN
  remains a manual start/submit fallback; stock LAFVIN behavior is unchanged.
- The Vertex gateway can declare two authenticated, read-only tools backed by
  the canonical Symbios Memory Bridge: `get_operational_brief` and
  `search_symbios_context`. The query bearer stays server-side. No repository,
  Notion, Pinecone, broker, or provider credential is sent to the ESP32.
- Standby status changes from the generic localized label to `SYMBIOS` only in
  the Symbios gateway build.

## Root cause closed by the hands-free change

The firmware already sends `listen.start` with mode `auto` after WakeNet. The
current Vertex bridge intentionally disables provider-side automatic activity
detection and sends explicit `activity_start` / `activity_end` events. Before
this candidate, the device emitted the matching stop only when DOWN was
pressed. The staged timer converts the already-working on-device speech/silence
transition into the same reviewed `listen.stop` path. It does not introduce a
second audio decoder, retain PCM, or change the gateway's binary audio format.

## Symbios awareness boundary

The private `pops-symbios` service states that the Memory Bridge is its single
retrieval interface. The gateway therefore calls only its authenticated
`POST /brief` and `POST /query` routes. Vertex Live receives tool results and
uses them to formulate the spoken answer. It never receives the bearer token.

The integration is fail-closed:

- both `SYMBIOS_CONTEXT_BASE_URL` and `SYMBIOS_CONTEXT_TOKEN` must be present;
- production requires HTTPS;
- responses are capped at 256 KiB and model-facing output at 12,000 characters;
- request time is bounded;
- HTTP errors are reduced to a generic spoken availability error;
- the write-capable `/session` route is not declared or callable.

The current Render free-tier Memory Bridge can cold-start after inactivity.
That is incompatible with a consistently low-latency voice promise. Before
production enablement, either keep the canonical service warm or deploy the
same service on an always-on target; do not create a parallel retriever.

## Exact “Hi Symbios” boundary

Changing a string or display label cannot change a neural wake model. The
currently working built-in English model recognizes “Hi ESP.” A real
“Hi Symbios” release requires an Espressif-compatible custom model, then:

1. verify the model's source, phrase, language, license, and checksum;
2. package only the reviewed model in `srmodels.bin`;
3. run quiet-room, near-field, far-field, false-positive, and playback tests;
4. retain DOWN and the prior “Hi ESP” assets as rollback paths;
5. review an assets-only hash before any write to the shared assets partition.

Until those gates pass, the truthful UX is a SYMBIOS-branded assistant that
still wakes to “Hi ESP.”

## APEX and portfolio screen boundary

The audited `apex-ultra` dashboard is a localhost, read-only view over
`snapshot.json`, normally regenerated by its M1 loop. Its book-reconciliation
rules require live broker positions before a held-position decision. It is not
a cloud quote API and its repository snapshots must not be presented as live.

The proposed 320×240 display is therefore split into two explicitly labeled
cards:

1. **Market card** — BTC and selected public assets from a server-side quote
   provider, with quote timestamp and `LIVE`, `DELAYED`, or `STALE` label.
2. **APEX card** — net liquidation, cash percentage, position count, risk flag,
   and APEX snapshot timestamp from a future authenticated, read-only export of
   the canonical APEX snapshot. No order, Council-run, broker-auth, or mutation
   control belongs on the device.

The gateway should send a compact data payload, not a remote arbitrary image.
The firmware should render fixed native widgets and reject unknown fields,
oversized values, invalid timestamps, and stale portfolio snapshots. This
display phase is intentionally not implemented in the hands-free/context
candidate because APEX currently has no reviewed authenticated export and the
user has not yet selected the public asset list or quote source.

## Review acceptance gates

### Gateway candidate

- Python tests and compile check pass.
- Vertex setup declares only the two read-only tools when the context secret
  pair is configured, and no tools otherwise.
- A mock authenticated brief/search round trip passes without token disclosure.
- A staging deployment uses a new Secret Manager binding scoped only to the
  query bearer and receives zero production traffic until reviewed.
- Authenticated live queries demonstrate acceptable warm and cold latency.

### Firmware candidate

- Stock LAFVIN and Symbios ESP-IDF 5.5.2 builds pass.
- Binary inspection finds one reviewed HTTPS gateway URL, SYMBIOS and
  auto-submit markers, the intended `wn9_hiesp` fallback, and no credential
  signatures.
- Auto mode: wake, speak, pause, and receive an answer without DOWN.
- Manual mode: DOWN, speak, DOWN still submits exactly once.
- Silence-only wake and sub-300 ms noise do not submit; a mid-sentence pause
  shorter than 1,200 ms does not submit; speaking again cancels a pending timer.
- Existing display, speaker, Wi-Fi, activation, mono MIC1, and rollback assets
  remain accepted.

No flash may occur until the exact merged/application hashes and protected-file
audit exceptions are presented for a separate explicit approval.
